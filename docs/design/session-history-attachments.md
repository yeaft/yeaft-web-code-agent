# Session 历史与附件读取

- **Agent 持有原件。** Session 上传写入 `sessions/<sessionId>/attachments`；旧的 Session 专属 `.claude-tmp-attachments` 仍可读取。持久 transcript 和发给模型的附件处理不变，不迁移、不回填。用户、模型和工具看到的是不同投影。
- **回放只携带引用。** 浏览器历史的初始页、向上翻页、增量和搜索跳转都不读取附件文件。每条附件仅含名称、类型和基于持久消息 ID 与附件序号的引用；路径和 Base64 不进入历史包。助手生成的图片仍走既有 `yeaft_asset_put` 资产通道。
- **展开才取内容。** Server 由引用生成同源 `/api/yeaft/session-attachments/...` URL。展开附件才读取图片，下载需点击。接口要求完整登录会话，按用户、Agent、Session 检查归属；浏览器不能直接发送内部附件读取消息。Agent 按当前可见的用户消息查附件，复用 Session 专属目录和文件读取限制。已删除、缺失、离线或越权只会导致附件请求失败，不影响已加载正文。
- **独立传输。** Server 不缓存新协议的附件，不持久化原件。每次最多从同一 Agent 读取 1 MiB，并进行请求/连接相关性和文件版本检查，按 HTTP 写入背压继续读取。只允许识别出的 PNG、JPEG、GIF、WebP 行内预览；其他文件仍可下载。大小限制：预览 10 MiB，下载 50 MiB。
- **历史也有字节预算。** 正文页使用实际序列化字节数决定分页，不仅依赖轮数。请求失败不再发送成功回执；无法分页的超大单条会明确报错，不跳过或改写原始内容。新 Agent 搭配旧 Server 时，正文和附件名称仍能加载，附件预览需要新 Server，发送失败也保留旧版超时行为而不发空成功页；新 Server 保留旧 Agent 已成功送达的旧预览，无法恢复旧 Agent 在本机丢弃的历史包。部署顺序为 Server/Web 在前，Agent 在后。
