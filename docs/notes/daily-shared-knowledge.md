# 统一世界：每日共享知识

每日共享知识是一个 Agent 本地后台 flow，不是两个 Skill，不新建 Session。它与 Dream、Work Center、旧 Share 及 auto-route 的决策无关。

## 启用和使用

在单用户 Agent 的实例目录 `<yeaftDir>/config.json` 中合并这一段（不要覆盖其他设置）：

```json
{
  "sharedKnowledge": { "enabled": true }
}
```

默认不开启，因为归纳会把经过筛选的历史文本发给该 Agent 已配置的主模型；摘要和索引留在 Agent 本机。修改设置后后台会重新读取。关闭只停止新归纳，不清除已落库的知识。

在统一世界的原生 Session 里可以问「我们之前定了什么发布流程？请查共享知识并标注来源」。模型按需调用只读 `SharedKnowledgeSearch`；结果是带来源的参考，不是指令，不自动注入每轮，不跨 Agent。不支持的旧版 Agent / Server 仍可以正常发送消息。

## 每日行为

- 每个本地日期凌晨 01:00 后运行一次。轮询间隔 5 分钟，Agent 在该时刻未运行则启动后补跑。离线多天只补最新已到期的一次，增量仍从各 Session 的成功位置继续，不为每天分别调用模型。
- 首次只供模型归纳首次尝试前五天的消息；之后以 Session 的消息序号为游标，按当次启动时刻冻结上界。定时任务、归档、明确来自其他 Session 的拷贝内容、工具、图片和中间进度不参与。短而明确的用户决定不需要等待助手回复。
- 同一个 flow 的第一个 Prompt 分段提取，第二个 Prompt 跨 Session 合并或去重。维度包括长期偏好、已确认决策、项目事实、工作线、成果和非敏感的稳定背景。没有有效条目时只更新游标，不积攒空摘要。
- 新表附加在 `session-discovery/discovery.db` 中，旧版本可忽略。后台 worker 读历史和写数据库，摘要及游标分批在同一事务提交。单个 Session 的格式或归纳失败不推进它的游标，其余 Session 可继续。无来源、无权访问、来源已归档或被清空，或者删掉了生成摘要时所用消息的条目，不会被新的查询返回。
- 首次为了确认日期窗口，后台 worker 可能需要读取更早的历史文件；不会把窗口前文本交给模型。单次 Session 读取有 256 MiB 上限，单文件沿用 8 MiB 上限，超限时不推进该 Session 的游标，其他 Session 仍可入库。后台输出只记录计数和失败类别，不输出原文或归纳正文。
