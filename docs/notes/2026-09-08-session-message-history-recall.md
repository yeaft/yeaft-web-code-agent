# Session 原始问答双桶历史召回

**日期**：2026-09-08

## 目标与范围

Yeaft 原生 Session 的自动历史上下文由两个桶组成：**优先争取最近 10 个完整 turn + 高相关最多 5 个旧 turn**。预算不足时从最近窗口的最旧端逐个缩减，并尽量保护最近 3 个 turn；新 Session 不足 3 个则保留全部。连 3 个完整 turn 也无法容纳时，先取消相关召回，再压缩这 3 个 turn 的临时 provider 副本，并仅回放最新 1 个 turn 的工具信息；正常窗口仍保留最新 3 个 turn 的工具信息。没有高相关结果就不召回，不用低相关内容凑数。当前正在执行的 turn 单独保护，两个历史桶共享剩余上下文预算。

相关召回针对当前 Session 持久记录中的原始 `user` 和 `assistant` 可见正文做全文检索，命中后读取对应的**完整问答 turn**，不是把搜索摘要或截断片段当作回答。全文表示检索对象是正文，而不是每次请求同步扫描所有 JSONL；索引、候选和读取都有上限。一个 turn 从真实用户消息开始，到下一条真实用户消息之前结束，可包含多条 assistant 正文。

此路径不依赖 Dream 生成的 `memory.md` / `summary.md` 自动召回，也不调用 Dream、fast model、embedding 或语义重排模型。Dream 仍可在后台维护记忆，Memory 工具和其他适用路径仍可使用记忆；不删除已有 memory 文件或数据库。本文只改变原生 Session 的自动历史选择，不把其他执行路径一并改造成消息召回。

## 配置契约

配置属于当前 Agent instance 的 `<yeaftDir>/config.json`：

```json
{
  "yeaft": {
    "recentTurnsLimit": 10,
    "relatedTurnsLimit": 5
  }
}
```

| 字段 | 默认值 | 范围 | 含义 |
| --- | --- | --- | --- |
| `yeaft.recentTurnsLimit` | 10 | 1..500 | 沿用持久配置与 UI bootstrap 兼容范围；provider 默认目标为 10，预算缩减保护下限为 3 |
| `yeaft.relatedTurnsLimit` | 5 | 0..5 | 高相关旧问答 turn 上限；0 关闭相关召回，不关闭最近历史 |

缺省或无效读取使用默认值；手改文件中的有限数值先向下取整，再夹到合法区间。数值字符串兼容读取和更新。新字段的 `null`、布尔值、空字符串和容器值不是有效数值，不应被误解释为关闭召回。设置 API 拒绝非数值和越界写入，不触碰原文件；合法小数按现有设置风格向下取整。旧客户端只更新并发数、归档期限或最近 turn 上限时，必须保留已有 `relatedTurnsLimit`，包括显式的 0；LLM、遥测等无关配置更新也不能丢失它。无需迁移既有实例配置；旧的 8/10 上限读取时收敛到 5，新写入只接受 0..5。recent 默认为 10，1..500 的持久配置兼容范围不变。不新增 UI 控件。

## 高相关门槛：可解释的规则，不是语义模型

候选来自原始正文全文索引，再按同一套确定性词法规则筛选：

- 从当前请求提取有限数量的有效词，过滤停用词、泛化请求和纯数字；保留路径、问题编号、snake_case、camelCase 等标识符。
- 所有命中（包括标识符）至少覆盖 60% 有效词，规则分数至少 6.5；普通词至少命中两个独立关键词。候选样本达到 8 个 turn 时，普通词和 camelCase / snake_case 标识符还须有至少一个命中词的样本频率不超过 50%。精确路径或问题编号可作为强锚点免于样本频率门槛，但不绕过覆盖度；路径、编号的子串不是精确命中。
- “继续”“之前说了什么”等泛化词、单个常见词或覆盖度过低的命中，不因索引返回了结果就进入相关桶。
- 排序和拒绝原因来自规则分数、命中词及来源元数据。它不理解同义改写，可能漏掉语义相关但词面不同的问答；不以额外 LLM 调用补救。

## Source fence 与 turn 身份

自动相关召回只接受当前 Agent 数据根、当前 Session 的来源。即使同属一个 Project，也不自动混入兄弟 Session；Project instruction 与工具显式历史搜索的职责不变。

检索文本与相关桶投影不含工具输出、tool call 参数、internal / reflection / thinking 内容、后台控制通知或其他伪装成用户消息的内部记录。相关桶只带 user + assistant 正文；最近桶的历史工具配对由既有 history-window 契约处理。当前 turn 不计入历史预算，而在完整请求窗口校验中处理。

最近历史以当前用户的持久序号为 exclusive 上界直接读取完整 turn，而不是从磁盘最新窗口读取后再过滤；因此排队期间新增的用户输入不会挤掉本轮之前的最近 10 个 turn。Provider reader 不复用 UI bootstrap 的 144 行分页截断，按稳定用户身份计数，工具行再多也不当成多个 turn；每扫描 64 行让出事件循环，扫描超过 32768 行或 64 MiB 时明确报读取上限，不静默发送残缺窗口。Web bridge 传递已持久化用户行；旧调用仅能在有界窗口内按 clientMessageId 找回身份，找不到时不猜测序号、不启用索引召回。

命中后按权威消息序号、用户边界与 source message IDs 还原完整问答，来源或时序不可确认时不猜测拼接。以 turn/source 身份去重，不能按 user 文本去重：用户两次问同样的话仍然是两个 turn，回答不能合并。最终 related 必须早于最终 recent 的边界，且与 recent/current 的来源不重叠。

## 统一 token 预算与重算

1. 默认 32768 token 的历史预算只分配给当前 turn 之前的消息；当前 turn 不占用该预算。
2. 先从最新端安置最近历史完整正文，默认争取 10 turn，并按 token 和 message 预算从旧到新连续降级。尽量保护 3 turn；若仍放不下，则取消 related、压缩这 3 个 turn 的临时副本，并仅保留最新 1 个 turn 的工具回放，不抛内部预算错误。
3. 不再为相关桶预留 25%。用最终 recent 以外的候选构建 related，按相关度挑选完整 turn，仅使用最近正文支付后的余额，最多 5 个。
4. 最终 wire 顺序为 related（内部按时间升序）→ recent（连续时间升序）→ 当前执行。召回不能挤占最近正文，不能与 recent/current 的来源重叠。
5. 不能先把初始“最近 10 个”永久排除出候选：某个 turn 因 token 预算从 recent 掉出后，只要符合来源、时序和相关门槛，仍可进入 related。
6. 历史问答以完整正文 turn 为预算单位。单个过大的相关 turn 整体跳过，继续考察其他候选；不能截断回答来凑够条数。超出索引读取边界的 turn 也不使用不完整片段。
7. 两桶与当前 turn 合并后，完整请求按实际模型窗口另行校验，计入 system、tool schemas、历史、当前 turn 与 output reserve；只有最近 3 个历史 turn 的工具配对可用历史余额回放，相关桶不带工具。每次 provider request 都重新构造临时窗口，必要时整组淘汰旧工具协议单元，query 内不调用摘要模型。

因此，“20 + 5”不保证每次实际携带 25 个历史 turn，也不保证极大问答一定能召回。

## 索引降级与可观察性

全文索引是可重建的派生数据，不是 transcript 真源。首次冷调用启动后台构建并立即返回 `not_ready`；已有索引在新消息 append 后落后，或已有构建正在进行时，本轮最多等待 **1500ms**（刷新和 worker 查询共用预算），超时不取消后台构建。返回 `not_ready` 时，本次自动召回降级为最近历史；不阻塞主请求等待无界全量扫描，不回退 Dream 内容凑数。状态与原因必须可观察，不能把 `not_ready` 伪报成正常的“没有相关结果”。空闲查询 worker 不保持 CLI 进程存活，有请求时才保持引用。

候选检索不是全库穷举证明：≥3 字符词每词只取固定前 32 个 trigram postings，再应用序号 fence；中文两字词检查最新 512 条符合范围的 entry metadata。因此通用前缀碰撞、时间边界或较旧的中文问答可能漏召回；`candidateCapped` 记录触及候选上限，`ready/no_match` 不能解释为全库确定无匹配。当前重建仍为完整后台重建，大 transcript 超过本轮等待预算时会降级。

诊断应能区分索引状态、候选/选中数量、规则命中、两桶来源 ID、预算预留与实际消耗，以及重复或超大 turn 的排除。诊断元数据不要求复制整段敏感正文。

## 不改变的数据与界面

此设计只构造给模型的临时上下文副本，不改写或删除持久 transcript，不生成新的 compact summary，不更改浏览器历史、分页、搜索结果或消息顺序。浏览器看到的完整持久历史与模型本次实际携带的窗口是两个数据层；相关召回不是向浏览器重复追加旧回答。
