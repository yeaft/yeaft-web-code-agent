删掉的用例只保留在 Git 历史里，不另建归档套件，不用 skip、过滤或合并无关场景来降低计数。发布语法检查、包入口检查、Server 启动 smoke 仍保留。

## 保留什么

- **权限与数据安全**：登录和连接代际、跨用户／Agent 隔离、文件访问、内容隔离；删轮次时保留相邻历史并阻止旧上下文复活。
- **核心工作流与恢复**：发送和流式回复、工具执行与取消、会话重连和历史回放、追加与并行、Fork/Merge；数字人、定时任务和 Work Center 各保留关键持久化或端到端链路。
- **三个原生 API 的关键边界和近期回归**：缓存默认及回退、签名状态和工具批次；Gemini v1、会话场景、数字人搜索及标题布局、整轮删除和新旧 Agent 混连。

优先删除重复的主题／视口矩阵、低风险展示细节、旧功能的细分分支，以及已被更高层关键链路覆盖的重复断言。**精简后的覆盖不等价于原套件**：旧功能、少见平台和错误分支的自动覆盖更少。修改这些路径时，按风险从 Git 恢复或新增针对性的回归即可，不必补回整套。

## 数量口径与门禁

用例数只统计，不设上限。`scripts/test-suite-manifest.mjs` 登记全部保留的 Vitest 与 Playwright 文件：

- `npm run test:count` 收集两个测试目录的逻辑用例。Vitest 的 skip／todo 和展开的参数化用例都计入；Playwright 的同一逻辑用例不会因配置多个 project 重复计数。旧命令 `npm run test:budget` 等价于 `npm run test:count`。
- 收集错误、文件缺失或未登记仍会失败；只收集不等于执行。
- `npm test` 执行全部保留的 Vitest 测试，检查收集完整性并报告用例数；`npm run test:e2e` 才实际执行浏览器测试。

## 新增与定期清理

随功能补最能防止严重回归的用例：优先覆盖权限、持久化、失败恢复和用户主路径。已有用例覆盖相同契约时，先更新它而不是再复制一套。新增或删除文件时，在同一 PR 更新清单并运行测试门禁。

每月人工盘点一次，参考 `npm run test:count` 和 CI 耗时，优先清理重复覆盖、已退役功能的测试和低价值的组合。删除时在 PR 说明替代覆盖，或说明行为已经下线。不因数量自动删除、跳过或排除用例。
