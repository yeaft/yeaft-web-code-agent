# 结构化回复

数字人与 Yeaft 原生 Session 可按需使用 `PresentResponse`，将已经获得的结果表达为更易阅读的结构化内容。普通短回答仍然直接使用文字；这不是每轮必经的「美化模型」，不会为渲染额外调用模型。

## 展示与边界

同一份版本化内容协议和前端组件服务两条链路；消息身份、执行生命周期及持久化仍分别归属于原生 Session transcript 与数字人的 owner-scoped 存储。

支持 Markdown、方案卡片、紧凑指标、对比表、柱状／折线图、时间线、关系图、图片、交付链接与地点坐标示意。组件的布局、颜色及几何由客户端控制，不接受模型提供的 HTML、CSS、JavaScript 或任意 SVG。

- 卡片用于实际分组，避免把所有段落装进重复的卡片外壳。
- 图表必须使用真实数据，并说明单位、来源和限制；渲染不会验证数据真实性。
- 地图第一版是明确标注的**坐标示意图**与地点列表，不加载外部地图瓦片，不是导航地图。不得凭空推测坐标。
- 外部图片需用户主动加载；外链仅接受无凭据的 HTTP(S)，Server／Agent 不抓取。查看会向对应站点发起浏览器请求，应注意隐私。此工具不生成图片，也不按路径读取本机文件。
- 已有本地图片、文件交付机制保持独立；不要用不受所有权校验的本机路径或其他 owner 的资源代替有效交付链接。

## Loop 中的语义

工具／能力首先校验全部内容，然后发布用户可见回复。非法类型、超限内容、不一致的表格／图表、不存在的关系端点及不安全 URL 均拒绝发布；模型可以修正参数或使用文字回复。

`phase: "progress"` 表示阶段性沟通；`phase: "final"` 表示交付意图，**不自行终止 turn、提交认知状态或证明任务完成**。Session 沿用引擎 terminal boundary；数字人仍由认知提案的 `next:null` 完成提交。发布后的取消／失败不能撤销已交付内容，执行中的状态也不能因存在 final 内容而变成成功。

不强制工具只能在最后调用。先展示有依据的部分结果，可以继续检查；完整结果发布后，不需要再重复输出相同长文。

## 协议示例

原生 Session 工具参数，以及数字人能力的 `args`，使用相同结构：

```json
{
  "title": "两种方案对比",
  "summary": "建议先选择方案 A：验证成本更低。下列成本仅为估计，尚未包含外部服务费用。",
  "phase": "final",
  "blocks": [
    {
      "type": "cards",
      "items": [
        { "title": "方案 A", "label": "建议", "text": "复用既有能力，先验证关键链路。" },
        { "title": "方案 B", "text": "单独建设，维护成本较高。" }
      ]
    },
    {
      "type": "table",
      "columns": ["方案", "改动范围", "验证"],
      "rows": [["A", "局部", "聚焦测试与浏览器"], ["B", "跨模块", "端到端与恢复"]]
    }
  ]
}
```

`summary` 必须独立可读，供复制、搜索、模型历史和旧客户端降级，不只是「见上图」。单次内容上限 48 KiB，最多 12 个 block；每种 block 还有条目、长度和维度限制。原生工具 schema 和数字人按需加载的完整能力契约描述实际字段。

## 兼容范围

- 原生 Session：通过内置工具按需发现、执行并发布，支持实时展示与持久历史回放。
- 数字人：通过能力目录发现、准备、调用，继续使用现有同 episode 分段展示。
- Claude Code／Copilot CLI Chat：前端组件可以复用，但其 CLI 工具协议不因原生工具注册而自动增加此能力。
- 旧消息没有结构化内容，保持原来的文字展示；不迁移旧 transcript 或运行数据。未知内容版本保留可读摘要。

## 验证关注点

变更需要同时覆盖协议校验、发布与终止分离、取消／失效执行权、持久化重开、实时与历史去重、身份隔离，以及 light／dark、320px 窄屏、桌面、长内容、键盘访问和外部图片失败。没有调用该工具的普通文字回答不应改变。
